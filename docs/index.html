A reference compiler and runtime in Rust

Concurrent programs with visible lifecycles.

ProgLang combines finite functions and routines with persistent, signal-driven loops. The compiler verifies termination boundaries and reports worst-case complexity before work reaches the runtime.

Design constraints

Make the useful boundaries explicit.

01

Finite work

Functions and routines must terminate. Persistent loops are checked one finite iteration at a time.

02

Isolated tasks

Each scheduled task receives an arena. When it completes, the arena disappears as one unit.

03

Named signals

Loops own FIFO mailboxes. A signal never waits for the loop that will consume it.

The language

Start deliberately. Spawn deliberately.

Programs begin at routine main(). Files without it are libraries. Routines are independent tasks; functions are the declarations that return values and may emit exceptions.

  • ✓ Bounded for loops; no while.
  • ✓ Structural recursion for finite functions.
  • ✓ try/catch everywhere; throw in functions.
Entry point + exception boundary
import std

routine main() {
  spawn Worker()
}

routine Worker() {
  try { parse("42") }
  catch error { std.log(error) }
}

Persistent loops

A loop is dormant until it is spawned.

Its first spawn starts it. Later spawns signal the already active instance instead of restarting it.

import std

routine Producer() {
  spawn Inbox("new work")
}

loop Inbox() {
  std.log(receive.value, receive.pending)
  terminate
}
// No argument starts the loop with no queued signal.
spawn Inbox()

// First iteration:
receive.value   // None
receive.pending // 0
