Guia prático

Escreva programas Lia que deixam claro quando e por que terminam.

Lia separa cálculo, concorrência e repetição persistente em três construções: func, routine e loop. Este guia mostra como combiná-las, como o compilador as verifica e como o runtime as agenda.

1. Comece 2. Modelo mental 3. Funções 4. Rotinas e main 5. Loops e sinais 6. Bibliotecas 7. Compilador e análise 8. Execução e interrupção

1 · Comece

Execute um arquivo .lia.

O repositório contém programas executáveis e bibliotecas. Um executável tem exatamente uma rotina chamada main; sem ela, o arquivo é uma biblioteca que apenas declara tipos, funções, rotinas ou loops para importação.

cargo testcargo test
cargo run -- programs/00_hello_world.liacargo run -- programs/00_hello_world.lia
cargo run -- --test-allcargo run -- --test-all
Regra de entrada: chamar um arquivo inicia somente main. O processo termina quando não há mais rotinas, funções ou loops ativos.

2 · Modelo mental

Escolha a construção pelo efeito que você precisa.

func

Calcula e retorna um valor. Pode chamar outras funções e usar recursão estrutural. É a única construção com retorno.

routine

Executa trabalho isolado. Não retorna valor; use spawn para iniciá-la concorrentemente.

loop

É um ator persistente com caixa postal FIFO. Não recebe parâmetros na declaração e não retorna valor.

std

Biblioteca padrão explícita. Importar std libera primitivas finitas como std.log, std.max e std.prepend.

3 · Funções

Retorne valores e diminua a entrada recursiva.

O compilador aceita recursão direta quando consegue ver que o argumento indutivo diminui. Em uma lista, o padrão Cons(head, tail) torna tail menor que a lista original.

Use match para tratar cada forma possível de um valor. O caso Nil cria a base; o caso Cons reduz a estrutura. Um ciclo mútuo como a → b → a é rejeitado pelo verificador do grafo de chamadas.

Importante: uma função pode lançar uma exceção com throw. Rotinas e loops podem usar try/catch, mas não lançam exceções diretamente.

4 · Rotinas e main

Agende trabalho sem compartilhar referências mutáveis.

Uma rotina é uma tarefa isolada. spawn cria trabalho independente; dados passados na chamada precisam ser copiáveis. Ref[T] permanece confinado à arena da rotina que o criou.

Cada rotina recebe uma arena local. Quando seu corpo termina, a arena inteira é descartada de uma vez; nenhuma referência local pode escapar para outra tarefa.

5 · Loops e sinais

Use loops para trabalho persistente, não para while.

Não existe while em Lia. Um loop fica dormente até receber spawn NomeDoLoop(). Se ele já estiver ativo, outro spawn NomeDoLoop(valor) envia um sinal para sua fila em vez de criar uma segunda instância.

  • ✓message.value contém o sinal entregue nesta iteração, ou None quando não há sinal.
  • ✓message.pending informa quantos sinais permanecem na fila após a entrega.
  • ✓Sem terminate, o loop agenda a próxima iteração depois de concluir a atual.

6 · Bibliotecas

Todo acesso ao runtime é declarado no fonte.

A biblioteca padrão não é implícita: importe std para usar suas primitivas. Ela contém somente operações certificadas como finitas sobre valores materializados, incluindo std.equals, std.less_or_equal, std.max, std.empty, std.prepend e std.log.

Arquivos cujo nome começa com número usam aspas no import. Uma biblioteca sem main não inicia trabalho ao ser carregada: ela apenas disponibiliza suas declarações.

7 · Compilador e análise

Valide antes de executar; pergunte pelo custo quando precisar.

O compilador analisa imports, constrói o grafo de chamadas, verifica tipos e confinamento de referências, prova redução estrutural e estima o pior caso de cada declaração. A análise de um loop descreve uma única iteração.

cargo run -- complexity programs/11_search_and_sort.lia func insertion_sortcargo run -- complexity programs/11_search_and_sort.lia func insertion_sort
cargo run -- compile programs/11_search_and_sort.lia -o search.liaccargo run -- compile programs/11_search_and_sort.lia -o search.liac
cargo run -- run search.liaccargo run -- run search.liac
Exemplo real: o compilador reconhece linear_search e insert_sorted como O(N); como insertion_sort chama uma inserção linear para cada elemento, seu pior caso é O(N²).

8 · Execução e interrupção

O runtime só trabalha enquanto houver tarefas pendentes.

Depois que main é iniciada, o runtime espera as rotinas disparadas e os loops ativos terminarem. Uma rotina comum libera sua tarefa quando o corpo termina. Um loop mantém uma única instância ativa e usa sua caixa postal FIFO para a próxima iteração.

Se o usuário emitir Ctrl + C, o runtime encerra as rotinas e loops ativos, descarta sinais pendentes e impede novos re-agendamentos.
